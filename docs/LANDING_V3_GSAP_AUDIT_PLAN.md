# Landing v3 — план правок по аудиту GSAP

**Откат (актуальный):** `backup/landing-v3-gravity-alpha/`  
**Откат (до gravity):** `backup/landing-v3-pre-spiral-idea/`  
**Откат (D5 applied):** `backup/landing-v3-d5-baked-cards/`  
**Откат (до аудита):** `backup/landing-v3-pre-gsap-audit/`  
**Фокус сейчас:** desktop (≥768px).  
**Мобила:** парковка — отдельная очередь после стабильного desktop.

Правило работы: **один шаг → проверка глазами/скроллом на компе → ок → следующий**. Не смешивать шаги в одном заходе.

### Не портить видимую анимацию

- Цель правок — производительность **без** заметной порчи драматургии.
- Если фикс «оптимальнее», но может изменить то, что видно (амплитуда, blur, тайминг, число карточек, характер birth чата и т.п.) — **сначала спросить**, не править молча.
- В вопросе коротко: **что меняем**, **чем жертвуем визуально**, **что выигрываем** (FPS / layout / GPU). Ждать явного «ок / правь».
- Чисто технические шаги без риска для картинки (например снять `will-change` в покое) можно предлагать сразу, но всё равно одним шагом и с проверкой после.

## Очередь desktop (по порядку)

| Шаг | Задача | Зачем | Файлы (ожидаемо) | Критерий «готово» |
|-----|--------|--------|------------------|-------------------|
| **D1** | Убрать твин `filter` на hub (blur при birth) | Самый дорогой paint на скролле | `landing-v3-main.js`, при необходимости CSS | Тот же визуальный «исчезновение дыры», без анимации `filter` |
| **D2** | Снимать `will-change` с float-wrap, когда float на паузе / `scene-settled` | Меньше лишних слоёв GPU в покое и после пина | `landing-hero-v3.1.css`, возможно `landing-styles.css` | В DevTools слои не висят на всех wrap после settled |
| **D3** | Chat birth: `width` / `left` → transform (`scaleX` / `x`) | Меньше layout thrashing в конце пина | `landing-v3-main.js`, CSS чата | Визуально как сейчас; layout не дёргается |
| **D4** | Zero-G на desktop: меньше одновременных infinite-твинов | 47× `repeat:-1` жрёт FPS ещё до скролла | `landing-v3-main.js` | Покачивание читается; idle FPS заметно спокойнее |
| **D5** | CSS `filter` на всех PNG-карточках | Коррекция цвета ×47 + scrub = дорого | ассеты и/или `landing-hero-v3.1.css` | Вид карточек близок к канону; без per-card filter в CSS |
| **D6** | Live `prefers-reduced-motion` (смена без reload) | Доступность, если юзер переключил ОС | `landing-v3-main.js` | Смена настройки → сцена/статика без F5 |
| **D7** | Спираль: снизить стоимость `onUpdate` × N карточек | Запас плавности scrub на слабом desktop | `landing-v3-main.js` | Scrub без микролагов; драматургия спирали сохранена |

## Вне скоупа этого плана

- SEO / копирайт / секции ниже hero (кроме побочного влияния ScrollTrigger refresh)
- Замена GSAP на другую библиотеку
- Рефакторинг «на всякий случай» без критерия из таблицы

---

## Чеклист после каждого desktop-шага

1. Жёсткий reload (Cmd+Shift+R).
2. Hero idle → лёгкое покачивание (если шаг не отключал float).
3. Медленный scrub до birth чата и обратно.
4. Быстрый скролл через пин и обратно вверх.
5. Resize окна desktop → сцена не «плывёт».
6. При сомнении — откат из `backup/landing-v3-gravity-alpha/`.
